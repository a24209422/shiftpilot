# 切換（階段 3）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docker compose up -d --build` 一個指令啟動整個系統，`http://127.0.0.1:8000/` 提供畫面與 API；舊 Streamlit 檔案從根目錄搬到 `legacy/`，README 改寫。

**Architecture:** 根目錄一個多階段 `Dockerfile`（Node 建前端 → Python 跑後端），映像檔內的目錄配置與 repo 相同（`/app/backend`、`/app/frontend/dist`），所以 `backend/app/main.py` 的 `defaultFrontendDir`（= `parents[2]/frontend/dist`）不用改。compose 加 `app` 服務，啟動時先 `migrate` 再 `uvicorn`。

**Tech Stack:** Docker 29、Docker Compose v5、`node:24-slim`、`python:3.13-slim`。

**Spec:** `docs/superpowers/specs/2026-11-21-cutover-design.md`（主設計：`docs/superpowers/specs/2026-11-20-erp-platform-design.md` 階段 3）

## Global Constraints

- 對外只綁 `127.0.0.1`；密碼只從 `.env` 帶入，不寫進 `Dockerfile` 或 compose；`.env` 不能進映像檔。
- 容器內不用 root 執行後端。
- `TZ=Asia/Taipei`。
- 註解用正體中文，只寫「為什麼」；YAML／Dockerfile 縮排 2 個空白。
- 驗證不能碰使用者現在的資料：用另一個 compose 專案名稱（`-p schedule-verify`）與不同的 port，跑完 `down -v`。
- 舊檔案用 `git mv` 搬，不刪除。

## Review Focus

1. **`.env` 跟著進映像檔**：`.dockerignore` 漏掉就會把密碼打包進去。→ Task 1 Step 4 檢查映像檔裡沒有 `.env`。
2. **migrate 失敗仍啟動**：要用 `&&` 串，migrate 失敗時容器停下而不是用舊結構跑。→ Task 1 的 compose 指令。
3. **資料庫還沒好就啟動**：`depends_on` 要用 `condition: service_healthy`。→ Task 1。
4. **port 只綁本機**：`127.0.0.1:${APP_PORT:-8000}:8000`，不能寫成 `8000:8000`。→ Task 1 Step 4 檢查 `docker compose port`。
5. **容器內的「今天」**：`TZ` 沒生效時首頁的「今天的排程」會用 UTC。→ Task 1 Step 4 在容器裡跑 `date` 與 Python 的 `datetime.now()`。

### Task 1: Dockerfile、.dockerignore、compose 的 app 服務

**Files:**
- Create: `Dockerfile`
- Modify: `.dockerignore`（整個改寫）、`docker-compose.yml`（加 `app`；postgres 的對外 port 改成 `127.0.0.1:${POSTGRES_PORT:-5433}:5432`，方便驗證時換 port）
- Modify: `.env.example`（加註解說明 `APP_PORT`、`POSTGRES_PORT` 可選，預設 8000、5433）

**Interfaces:**
- 映像檔配置：`/app/backend`（後端程式與 `requirements.txt` 安裝結果）、`/app/frontend/dist`（前端建置結果），工作目錄 `/app/backend`，使用者 `app`（非 root）。
- `app` 服務：`environment`：`DATABASE_URL=postgresql://schedule_app:${APP_DB_PASSWORD:?…}@postgres:5432/schedule`、`TZ=Asia/Taipei`；`command`：`sh -c "python -m app.cli migrate && exec uvicorn app.main:createAppFromEnv --factory --host 0.0.0.0 --port 8000"`；`ports`：`127.0.0.1:${APP_PORT:-8000}:8000`；`depends_on: postgres: condition: service_healthy`；`restart: unless-stopped`；`healthcheck` 用 Python 打 `http://127.0.0.1:8000/api/auth/me`，回 401 就算健康（不用額外裝 curl）。
- `.dockerignore`：`.env`、`.git`、`legacy/`、`prototype/`、`docs/`、`.superpowers/`、`frontend/node_modules/`、`frontend/dist/`、`backend/tests/`、`**/__pycache__/`、`**/.pytest_cache/`、`*.db`。

- [ ] **Step 1: 寫 Dockerfile** — 第一階段 `FROM node:24-slim AS frontend`：`WORKDIR /app/frontend`、先複製 `package.json` 與 `package-lock.json` 跑 `npm ci`（快取層），再複製其餘前端檔案跑 `npm run build`。第二階段 `FROM python:3.13-slim`：`ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1`、建立使用者 `app`、`WORKDIR /app/backend`、先複製 `backend/requirements.txt` 跑 `pip install --no-cache-dir -r requirements.txt`，再複製 `backend/`、`COPY --from=frontend /app/frontend/dist /app/frontend/dist`、`USER app`、`EXPOSE 8000`。
- [ ] **Step 2: 改寫 `.dockerignore` 與 `docker-compose.yml`、`.env.example`**（如上）。
- [ ] **Step 3: 設定檢查** — `docker compose config -q`。預期：沒有輸出、結束碼 0。
- [ ] **Step 4: 從空的 volume 驗證**（不碰使用者的資料）：
  - `APP_PORT=8010 POSTGRES_PORT=5440 docker compose -p schedule-verify up -d --build --wait`。預期：兩個容器都 healthy。
  - `docker compose -p schedule-verify logs app`：預期看到「已套用 org/0001_org.sql」等三行。
  - `docker compose -p schedule-verify port app 8000`：預期 `127.0.0.1:8010`。
  - `docker compose -p schedule-verify exec app sh -c 'whoami; date; python -c "import datetime; print(datetime.datetime.now())"; ls -a /app/backend /app'`：預期 `app`、台灣時間（比 UTC 快 8 小時）、看不到 `.env`。
  - `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8010/` → `200`；`/bookings` → `200`；`/api/auth/me` → `401`。
  - 建管理員與示範資料：用 `docker compose -p schedule-verify exec -T app python -c` 呼叫 `app.cli.createUserCommand(…)`（驗證用，不經過互動輸入）與 `seedDemoCommand`；再用 curl 走一次：登入 → 建員工 → 建資源 → 建排程 → 同一資源同一時段再建一次，預期第二次回 409 `RESOURCE_CONFLICT`。（中文 JSON 用檔案帶入 `--data-binary @file`，避免 Windows 終端機編碼問題。）
  - 重啟容器 `docker compose -p schedule-verify restart app` 後 logs 出現「沒有新的遷移」。
  - 清掉：`docker compose -p schedule-verify down -v`。
- [ ] **Step 5: Commit** — `git add Dockerfile .dockerignore docker-compose.yml .env.example && git commit -m "Docker：一個指令啟動前後端"`
