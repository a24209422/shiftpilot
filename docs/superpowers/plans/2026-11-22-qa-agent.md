# 問答 agent 模式 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 問答新增可切換的 agent 模式：模型用原生 tool calling 多步呼叫三個工具（`run_sql`、`find_available_people`、`get_busy_periods`），舊流程保留，評測能分模式量分數。

**Architecture:** 模型層新增 `callModelWithTools`，對內用中立的訊息格式，送出前才轉成 Ollama／OpenAI 相容格式。工具（`tools.py`）全部在既有沙盒連線上用參數化 SQL 執行。迴圈（`agent.py`）最多 4 次工具呼叫。`service.ask` 依 `mode` 分流，評測加 `--mode`，面板加模式切換與步驟清單。

**Tech Stack:** Python 3 / FastAPI / psycopg 3 / httpx / pytest；React + TypeScript / vitest；Ollama `/api/chat`、OpenAI 相容 chat completions。

**Spec:** `docs/superpowers/specs/2026-11-22-qa-agent-design.md`

## Global Constraints

- 縮排 2 個空白；變數、函式用 camelCase；註解用正體中文，只寫「為什麼」
- 工具呼叫上限 4 次（`maxToolCalls = 4`）；給模型看的資料列最多 20 列（`modelRowLimit = 20`），附總筆數
- 「有空」：當天的班蓋住整段時間，而且 `busy_periods` 沒有重疊；不考慮休息時間
- 模式值只有 `pipeline`、`agent`；API 沒帶 `mode` 時讀環境變數 `QA_MODE`，沒設時是 `pipeline`
- 回答句 fallback 固定是 `f"查到 {n}{' 筆以上' if truncated else ' 筆'}資料。"`（沿用 `composeAnswer` 的文字）
- agent 失敗沿用錯誤碼 `QA_QUERY_FAILED`；計分函式（`evals/scoring.py`）不動
- **不打開 `backend/evals/heldout_cases.py`**；test 只看總分。工具不得針對已知 test 破口（週六班、某時段誰有空、本月預約數）調整
- 雲端模型：沒估價、沒經使用者同意，不呼叫
- commit 之前先確認使用者同意（使用者規則：只在要求時 commit）

## Review Focus

1. 模型給的參數型別錯、缺必填、日期格式亂寫（`"明天下午"`）→ 回錯誤文字給模型，迴圈繼續，不丟例外（Task 3 `testBadArgumentsReturnError`）
2. 模型一輪就送出超過上限的 `tool_calls`（例如 6 個）→ 只執行到第 4 個，之後直接收尾（Task 4 `testToolCallsInOneTurnRespectCap`）
3. 模型呼叫不存在的工具名稱、或雲端回的 arguments 不是合法 JSON → 回錯誤文字給模型（Task 2 `testCloudInvalidArgumentsJsonKeepsRaw`、Task 3 `testUnknownToolReturnsError`）
4. 員工身分用工具查別人的請假 → 結果只有「請假」標籤，沒有假別或事由（Task 3 `testBusyPeriodsDoNotLeakLeaveDetails`）
5. 模型沒呼叫工具、直接把 `<tool_call>{...}` 當純文字回（小模型常見）→ 不把那段文字當回答顯示，回 `QA_QUERY_FAILED`，評測記成答錯並標 `noTool`（Task 4 `testDirectAnswerWithoutToolsFails`、Task 6 `testNoToolIsWrongWithFlag`）

工具參數：

| 工具 | 必填 | 選填 |
|---|---|---|
| `run_sql` | `sql` | — |
| `find_available_people` | `start`、`end` | `department` |
| `get_busy_periods` | `start`、`end` | `employee`、`resource`（擇一） |

時間用 `datetime.fromisoformat` 解析（接受 `YYYY-MM-DD HH:MM` 與 `YYYY-MM-DD`）；`end < start` 是錯誤。`department`、`employee`、`resource` 以參數傳入 `LIKE '%' || %(x)s || '%'`。

`find_available_people` 的 SQL（語意由 spec 決定，照這個寫）：

```sql
SELECT DISTINCT e.name, d.name AS department, e.employee_no
FROM employees e
LEFT JOIN departments d ON d.id = e.department_id
JOIN day_shifts s ON s.employee_id = e.id
WHERE s.start_at <= %(start)s AND s.end_at >= %(end)s
  AND (%(department)s::text IS NULL OR d.name LIKE '%%' || %(department)s || '%%')
  AND NOT EXISTS (SELECT 1 FROM busy_periods b WHERE b.employee_id = e.id
    AND b.start_at < %(end)s AND b.end_at > %(start)s)
ORDER BY e.employee_no
```

（回傳時去掉 `employee_no` 欄，只留 `name`、`department`）

`get_busy_periods` 回傳欄位固定為 `who, start_at, end_at, kind, label`：

- 有 `resource`：`bookings` + `booking_resources` + `resources`，`who` 是資源名稱，`kind` 固定 `'meeting'`，`label` 是排程標題
- 否則：`busy_periods` join `employees`，`who` 是員工姓名；有 `employee` 時加姓名 LIKE 條件
- 時間重疊條件：`start_at < %(end)s AND end_at > %(start)s`，依 `start_at` 排序

**Interfaces:**
- Consumes: `tools.executeTool`、`tools.formatForModel`、`tools.toolDefinitions`、`llm.ToolReply`、`llm.ToolCall`、`sqlguard.stripThink`
- Produces:
  - `prompt.buildAgentMessages(question: str, data: SandboxData, now: datetime) -> list[dict]`：system prompt 含角色、工具使用原則（「誰有空」用 `find_available_people`，查某人或某資源有沒有事用 `get_busy_periods`，其他用 `run_sql`；查完用一兩句正體中文回答，不提 SQL）、`schemaText`、詞彙、`buildDateReference(now)`、資料範圍。**不放 few-shot**
  - `maxToolCalls = 4`
  - `@dataclass AgentOutcome: answer: str; result: ToolResult | None; steps: list[dict]; toolCalls: int; exhausted: bool; promptTokens: int; completionTokens: int`
  - `steps` 每一筆：`{"tool": str, "arguments": dict | None, "rowCount": int | None, "error": str | None}`
  - `runAgent(conn, toolLlm, model: str, messages: list[dict]) -> AgentOutcome`：`toolLlm(model, messages, tools) -> ToolReply`

迴圈規則：

1. 呼叫 `toolLlm`；累加 token（`None` 當 0）
2. 有 `toolCalls`：先把 assistant 訊息（中立格式）加進對話，再依序執行。每執行一個就 `toolCalls += 1`，並加一則 tool 訊息（`formatForModel`）。成功的結果記成 `lastResult`。已經到 `maxToolCalls` 就不再執行剩下的，`exhausted = True`，結束迴圈，**不再呼叫模型**
3. 沒有 `toolCalls`：`answer = stripThink(content).strip()`，結束
4. 結束後：`exhausted` 或 `answer` 是空字串，而且有 `lastResult` 時，`answer` 用 fallback 文字
