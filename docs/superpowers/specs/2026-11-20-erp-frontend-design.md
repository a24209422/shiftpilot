# 設計補充：前端（階段 2）

日期：2026-11-20　｜　規模：專案（`2026-11-20-erp-platform-design.md` 的階段 2）　｜　狀態：**已核准（2026-11-20）**

這份是主設計「前端」一節的補充，只寫這個階段多決定的事；主設計的目標、反目標、權限表照舊有效。

## 目的

把 `prototype/home-layout.indie-sleaze.chat-panel.prototype.html` 的外觀接上已完成的後端，變成能登入、真的讀寫資料的畫面。後端有、畫面沒入口的動作，用原型的樣式補上按鈕或表單，**不求精緻，使用者之後自己調整**。

## 做法比較

| 做法 | 取捨 | 結果 |
|---|---|---|
| 直接改原型 HTML（純 JS、字串拼 HTML） | 不用建置；但登入、權限、十幾個表單與錯誤處理塞進一個檔案，很快難改，沒辦法寫元件測試 | 不採用 |
| React 重做，CSS 整份搬過去（主設計已選） | 要 Node 建置；元件可以測，之後調整只改對應元件或一份 CSS | **採用** |

技術沿用主設計：Vite、React、TypeScript、React Router、TanStack Query、Vitest 與 Testing Library。這台電腦有 Node 24、npm 11。

## 決定

**頁面**（導覽列與首頁方塊由模組登記產生，用 `/api/modules` 篩掉沒權限的）

| 頁面 | 內容 | 誰看得到 |
|---|---|---|
| 首頁 | 今天的排程、下一場、會議室現況、數量（`/api/booking/summary`） | 全部 |
| 排程 | 以「週」為單位的列表，上一週／本週／下一週切換；可勾「含已取消」 | 全部 |
| 資源 | 列表與詳情；新增、編輯、停用 | 讀：全部；寫：管理員 |
| 員工、部門 | 列表與詳情；新增、編輯、停用、離職日 | 讀：全部；寫：人資、管理員 |
| 行事曆 | 假日、補班日；新增或修改某天、刪除某天 | 讀：全部；寫：人資、管理員 |
| 帳號 | 建立、改角色、停用、連結員工、重設密碼 | 管理員 |
| 稽核 | 稽核紀錄列表，往前載入更多 | 管理員 |

- **登入頁**：同一套風格。登入失敗、帳號被鎖、session 過期被登出、沒有權限，都要有明確的畫面或訊息。
- **自己的帳號**：側邊欄底部顯示目前登入者，有「改密碼」與「登出」。
- **新增與編輯**：表單放在原型的右側詳情面板（drawer）裡，不另外做彈出視窗。停用、取消排程是面板底部的按鈕。
- **權限**：沒權限的按鈕不顯示（後端照樣擋）。排程的「編輯」「取消」只在自己建立的或有 `booking.writeAny` 時顯示。
- **衝突**：資源撞期（`RESOURCE_CONFLICT`）在表單裡列出撞到哪一筆；參加者警告（`PARTICIPANT_CONFLICT`）列出原因，給「仍要排」按鈕，按了就帶 `acknowledgeWarnings: true` 重送。
- **錯誤**：其他錯誤顯示後端 `error.message`；欄位驗證錯誤盡量標在欄位旁。
- **送出方式**：`npm run build` 後由 FastAPI 在同一個網址提供畫面（`/` 是畫面、`/api` 是 API，未知路徑回 `index.html` 交給前端路由）；沒有建置結果時後端照常只提供 API。開發時用 Vite dev server，`/api` proxy 到 `127.0.0.1:8000`。
- **所有非 GET 請求**帶 `X-App-Client: web`。
- **字體**打包進前端（Oswald、Special Elite），不從 Google Fonts 載入。
- **拿掉**：假資料、「DEMO DATA」標籤、「模擬新增模組」按鈕、請假頁與「待審核請假」方塊、聊天面板。外殼保留右側面板的位置（之後問答直接掛上去），原型的收合、拖曳寬度程式碼這階段不搬。
- `prototype/` 放進 git 當參考，標明是一次性原型。
- 工作接在 `platform-backend` 分支上（後端還沒合併回 `main`）。

## 寫入動作核對表

每一列都要有畫面入口，這是本階段的驗收清單。

| API | 畫面入口 |
|---|---|
| `POST /api/auth/login` | 登入頁 |
| `POST /api/auth/logout` | 側邊欄「登出」 |
| `POST /api/auth/password` | 側邊欄「改密碼」 |
| `POST /api/core/users`、`PATCH /api/core/users/{id}` | 帳號頁「新增帳號」、詳情「編輯」 |
| `POST /api/core/users/{id}/password` | 帳號詳情「重設密碼」 |
| `POST /api/org/departments`、`PATCH …/{id}` | 部門頁「新增部門」、詳情「編輯」 |
| `POST /api/org/employees`、`PATCH …/{id}` | 員工頁「新增員工」、詳情「編輯」「停用」 |
| `PUT /api/org/calendarDays/{day}`、`DELETE …/{day}` | 行事曆頁「新增日期」、詳情「編輯」「刪除」 |
| `POST /api/booking/resources`、`PATCH …/{id}` | 資源頁「新增資源」、詳情「編輯」「停用」 |
| `POST /api/booking/bookings`、`PATCH …/{id}` | 排程頁與首頁「新增排程」、詳情「編輯」 |
| `POST /api/booking/bookings/{id}/cancel` | 排程詳情「取消排程」 |

## 非目標

- 月曆、時間軸視圖（主設計已排除）
- 精緻的表單設計、動畫、手機版細修（使用者之後自己調整）
- 聊天面板與問答
- Docker 與切換（階段 3）

## 怎麼驗證

- Vitest：API 客戶端（帶標頭、錯誤格式）、模組登記與權限篩選、衝突與「仍要排」流程、登入與被登出。
- 手動走一輪：用管理員登入，對核對表每一列操作一次；再用一般員工登入，確認寫入按鈕只出現在該出現的地方。

## 留給建造者

- 元件怎麼切、狀態怎麼放、目錄細節
- 表單欄位的排版與輸入元件（多選資源、參加者用什麼元件）
- 型別定義怎麼對應 API 回應
